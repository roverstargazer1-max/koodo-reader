# Full-Book AI Translation Specification

## Problem Statement

Readers who possess foreign-language books in Koodo Reader currently only have access to inline selection translation ("划词翻译") or dynamic single-chapter preview translation while reading. Readers cannot translate an entire book in advance, nor can they generate an independent, permanent translated edition in their library. 

Moreover, attempting whole-book translation with standard Large Language Models (LLMs) faces fundamental hurdles:
1. **Context & Output Limit Overflow**: Complete books (ranging from 50,000 to hundreds of thousands of words) far exceed LLM context windows and maximum generation output tokens (typically 4,000 to 8,192 tokens per request). Sending massive blocks causes truncation, hallucinations, or dropped paragraphs.
2. **Loss of Terminology & Narrative Continuity**: Translating chapters in isolation causes character names, pronouns, honorifics, and worldbuilding terminology to change randomly across chapters.
3. **Format & Image Destruction**: Simply running text through an LLM destroys book packaging, CSS styling, chapter spine hierarchies, and inline illustrations or images.
4. **Network Volatility & API Rate Limits**: A whole-book translation job can take 15 to 45 minutes; network disconnects, API rate limits (HTTP 429), or application restarts force users to restart from scratch, wasting expensive API tokens.

## Solution

Implement an automated, offline-first **Full-Book AI Translation Pipeline** integrated directly into Koodo Reader's library manager (external shelf view):

1. **Format-Preserving Text Deconstruction & Reconstruction**: Strictly focus on EPUB and TXT formats. For EPUB, parse internal XHTML files, extract translatable leaf text nodes with bidirectional index mappings, and inject translations back into the original DOM tree, guaranteeing **100% untouched images, figures, SVGs, and CSS formatting**, before repackaging as a valid EPUB via ZIP archives.
2. **Four-Tier Hierarchical Memory Architecture**:
   - **L1 (Local Context)**: A sliding window of immediate preceding translated paragraphs.
   - **L2 (Chapter State)**: Dynamic summary of plot events and character statuses, automatically generated by a lightweight LLM step upon chapter completion.
   - **L3 (Global Knowledge Base)**: A cumulative, self-updating dictionary of characters, honorifics, world rules, and recurring terminology maintained across the entire book.
   - **L4 (Historical Translation Corpus)**: A permanent local index of all source-target paragraph pairs powered by SQLite FTS5 full-text keyword retrieval (with optional external vector embedding RAG), recalling previous translations of key terms into the prompt.
3. **Chunked Hierarchical Pipeline**: Segment text logically by Chapter → Scene → Paragraph, enforcing batches of 1,000 to 4,000 source tokens per chunk, processed serially within each chapter to maintain narrative coherence.
4. **Lifecycle & Resilient State Machine**: Persist progress paragraph-by-paragraph to local storage. Provide 3-attempt exponential backoff on HTTP 429/503 errors before safely pausing. Support background execution with a floating progress badge, and automatic "Resume Interrupted Translation" upon app restarts.
5. **Direct Library Auto-Import**: Generate a new book named `<Original Title> (<Target Language> Edition)` (user-editable), retain the original cover and shelf placement, tag with a "Translation" label, and automatically register it into the library.

## User Stories

### Library Entry & Triggering
1. As a reader, I want to right-click any book card on the bookshelf to see a "Translate Book" option directly in the first-level context menu, so that I can initiate translation without entering the reading mode.
2. As a reader, I want the "Translate Book" option to be disabled or grayed out with an explanatory tooltip when right-clicking unsupported formats (such as PDF, MOBI, AZW3, CBR), so that I know only EPUB and TXT are currently supported.
3. As a reader, I want to find a "Translate Book" action button inside the Book Details dialog, so that I have multiple convenient ways to launch translation.

### Configuration & Customization
4. As a reader, I want a configuration modal to appear when I click "Translate Book", showing the book title, word count, estimated chapters, and file format.
5. As a reader, I want to select the source language (with an "Auto-detect" default option) and target language from a dropdown, so that the system knows the translation direction.
6. As a reader, I want the target language dropdown to default to my current Koodo Reader user interface language, saving me from redundant manual selection.
7. As a reader, I want the translation model to default to my pre-configured AI Translation Model from Settings -> AI Service, while allowing me to pick any other configured LLM provider for this specific book.
8. As a reader, I want to view and edit the system translation prompt with a high-quality literary translator prompt pre-filled, so that I can provide custom style guidelines or translation tones.
9. As a reader, I want a "Save as Default Prompt" toggle in the modal, so that my customized prompt can be reused across future book translations.
10. As a reader, I want to choose between "Pure Target Language Edition" (default) and "Bilingual Parallel Edition" (source paragraph followed by target paragraph), so that I can create books suited for either pure leisure reading or language learning.
11. As a reader, I want the output book title field to default to `<Original Title> (<Target Language> Edition)`, while allowing me to freely edit the title before translation starts.

### Execution & Background Task Management
12. As a reader, I want to view a real-time progress dashboard displaying current chapter, overall percentage (0-100%), translated word count, and estimated time remaining.
13. As a reader, I want to minimize the progress dashboard into a floating badge or widget at the corner of the screen, so that I can continue reading other books or browsing my collection while the background task runs.
14. As a reader, I want to click on the minimized floating badge at any time to restore the full translation progress modal.
15. As a reader, I want to pause the translation task at any time, so that I can pause token consumption or free up system resources.
16. As a reader, I want to cancel an active translation task with a confirmation prompt, so that I can safely abort unwanted jobs and clean up temporary state.
17. As a reader, I want active translation to automatically retry up to 3 times with exponential backoff (2s, 4s, 8s) when encountering API rate limits (HTTP 429) or network timeouts, so that temporary connection blips do not abort the process.
18. As a reader, I want the system to safely pause and notify me if retries are exhausted, so that my translated progress is never lost and I can resolve API credit issues before resuming.
19. As a reader, I want the system to persist translation progress paragraph-by-paragraph to local storage, so that if the application or system abruptly closes, I am prompted to "Resume Translation" upon reopening.

### Memory & Quality Assurance
20. As a reader, I want the translation prompt to dynamically receive relevant character names, terms, and worldbuilding rules (L3 Global Knowledge), so that proper nouns remain consistent across all 50+ chapters.
21. As a reader, I want each chapter's translation to be informed by the preceding chapter's plot summary (L2 Chapter State), so that narrative continuity and scene tone carry over smoothly.
22. As a reader, I want key recurring phrases to recall their previous translation via local SQLite FTS5 RAG retrieval (L4 Historical Corpus), so that fixed idioms and motifs are translated consistently.
23. As a reader, I want the L1 local sliding window to supply the immediate prior paragraphs, so that pronouns (he/she/they/it) and dialogues are accurately resolved.

### Reconstructed Book & Library Integration
24. As a reader, I want translated EPUB books to retain all original cover images, chapter illustrations, SVGs, and text styling, so that the reading visual experience is identical to the original edition.
25. As a reader, I want translated EPUB files to have their internal `content.opf` metadata updated (`dc:title`, `dc:language`), so that third-party e-readers and Koodo Reader parse the book metadata correctly.
26. As a reader, I want the completed translated book to be automatically added to the Koodo Reader database and file storage without manual export/import steps.
27. As a reader, I want the translated book to inherit the original book's cover thumbnail and shelf assignment, so that it sits neatly beside the original book in my library.
28. As a reader, I want the new book to automatically receive a "Translation" tag, so that I can quickly filter and search for translated works across my library.
29. As a reader, I want a success notification upon completion with an "Open Book" action button, allowing me to start reading the newly translated edition immediately.

## Implementation Decisions

### 1. Primary Architectural Seam: `BookTranslator` Engine
The entire translation workflow is decoupled from the UI and encapsulated behind a single high-level engine interface:
- **Input**: Source book binary buffer, file format (`epub` | `txt`), metadata, target language, LLM configuration, layout mode, and translation prompt.
- **Output**: Reconstructed book binary buffer, updated metadata, and library persistence.
- **Events / Observable**: Progress callbacks (`chapter`, `percent`, `words`, `timeRemaining`, `status`: `idle` | `running` | `paused` | `completed` | `error`).

### 2. Format Deconstruction & Safe DOM Reconstitution
- **EPUB Processing (`EpubProcessor`)**:
  - Unpack EPUB archives in-memory using `JSZip`.
  - Parse `META-INF/container.xml` to locate OPF manifest and spine.
  - Sequentially process each XHTML item in the spine order:
    - Parse into a DOM tree using standard `DOMParser`.
    - Recursively collect translatable text nodes via DFS, skipping non-content tags (`<style>`, `<script>`, `<pre><code>`, `<svg>`).
    - Store text nodes in an indexed array with parent pointers.
    - **Crucial Rule**: `<img>`, `<picture>`, `<figure>`, `<a>`, and styling attributes (`class`, `style`, `id`) are strictly preserved and never passed to the LLM.
    - Re-inject translated text into target nodes:
      - In **Pure Translation** mode: replace `node.textContent`.
      - In **Bilingual** mode: duplicate block nodes or append translated spans with dedicated CSS styling (`.koodo-translated-subtext`).
  - Update `content.opf` metadata (`<dc:title>`, `<dc:language>`) and repackage into a valid `.epub` via `JSZip`.
- **TXT Processing (`TxtProcessor`)**:
  - Segment text into chapters via standard regex patterns (e.g., `/(?:第[0-9一二三四五六七八九十百千万]+[章回节卷]|Chapter\s+\d+)/i`).
  - Batch paragraphs into 1,000-4,000 token slices.
  - Reconstruct clean UTF-8 text with translated paragraphs.

### 3. Four-Tier Memory Architecture (`TranslationMemory`)
The prompt sent to the LLM for every chunk strictly follows this structural payload:
```
[System Prompt & Translation Rules]
[L3: Global Knowledge Base - Characters, Honorifics, Recurring Terminology]
[L2: Chapter State - Prior Chapter Summary & Character Status]
[L4: Historical Context - RAG Top-K Similar Translated Pairs from SQLite FTS5]
[L1: Local Context - Last 2-3 Preceding Translated Paragraphs]
[Current Chunk to Translate]
```
- **L1 (Local Context)**: In-memory FIFO queue of the last 3 translated paragraphs of the current chapter.
- **L2 (Chapter State)**: When a chapter completes, an asynchronous lightweight LLM call (`max_tokens: 300`) analyzes the chapter and produces a concise summary.
- **L3 (Global Knowledge)**: Following chapter summary extraction, the LLM extracts newly introduced entities, names, and glossary terms. These are merged into a persistent key-value dictionary with deduplication.
- **L4 (Historical Corpus RAG)**:
  - Paragraphs and their translations are written to a local SQLite virtual table (`translation_fts USING fts5(book_key, source_text, target_text)`).
  - For the current chunk, proper nouns and keywords are queried against FTS5 to retrieve up to 3 most relevant historical translation pairs.
  - Architecture retains extension hooks for optional external vector embeddings.

### 4. Resilient Lifecycle & State Machine (`TaskStorage`)
- **State Storage**: The active job state is stored in IndexedDB (`translation_tasks` table) after every chunk. State records: `bookKey`, `currentChapterIndex`, `currentParagraphIndex`, `completedChunks`, `L1State`, `L2State`, `L3State`.
- **Retry Mechanism**: Wrapped with exponential backoff:
  - 1st failure: wait 2 seconds.
  - 2nd failure: wait 4 seconds.
  - 3rd failure: wait 8 seconds.
  - 4th failure: transition task state to `PAUSED_ERROR`, notify user.
- **Recovery**: Opening the translation modal for a book with an active/paused state in `translation_tasks` presents a "Resume Task" dialog.

### 5. UI Integration
- **Context Menu (`ActionDialog`)**: Add "Translate Book" directly under "Details". If the format is not EPUB or TXT, disable the row and show a localized tooltip.
- **Book Details (`DetailDialog`)**: Add a "Translate Book" secondary action button.
- **Translate Dialog (`TranslateBookDialog`)**:
  - Modal with tabs or stepped layout: Settings Step & Live Progress Step.
  - Allows minimizing to a non-intrusive floating progress badge (`TranslationWidget`).
- **Library Auto-Registration**:
  - Upon completion, invokes `BookUtil.addBook(newKey, format, newBuffer)`.
  - Extracts cover via `CoverUtil.addCover(newBook)`.
  - Saves record to IndexedDB/SQLite via `DatabaseService.saveRecord(newBook, "books")`.
  - Adds book key to original shelf in `ConfigService.getAllMapConfig("shelfList")`.
  - Adds "译本" tag to `ConfigService.getAllMapConfig("tagList")`.
  - Dispatches `handleFetchBooks()` to refresh the active shelf view.

## Testing Decisions

### 1. Behavior-Focused Testing Principles
- Tests must strictly verify observable external behavior and artifacts, never internal private state or intermediate variables.
- Verifications center on:
  - **EPUB Structure Validity**: Validating that reconstructed EPUB files contain valid XML, intact images, unchanged asset manifests, and readable spine items.
  - **Translation Invariance**: Ensuring non-translatable nodes (image tags, code blocks, styles) remain byte-for-byte identical after processing.
  - **Memory Evolution**: Verifying that L2 summaries and L3 glossary entries update sequentially across multi-chapter runs.
  - **Interruption & Resumption**: Simulating network aborts midway and verifying that resumption starts from the exact uncompleted chunk without duplicate token requests.

### 2. Modules to Test
- `EpubProcessor`: Unit tests using sample EPUB files containing complex XHTML, nested divs, inline images, and multi-level TOCs.
- `TxtProcessor`: Regex splitting, paragraph batching, and bilingual reconstruction tests.
- `TranslationMemory` & SQLite FTS5: Database creation, keyword query matching, and prompt assembly tests.
- `BookTranslator` State Machine: Mock LLM harness verifying serial execution, error retry backoff, pause/resume transitions.

### 3. Prior Art in Codebase
- Book backup and restore zip packaging: `src/utils/file/backup.ts`, `src/utils/file/restore.ts`.
- Local database and storage operations: `src/utils/storage/databaseService.ts`.
- AI request & streaming helpers: `src/utils/request/common.ts`.

## Out of Scope

1. **PDF / MOBI / AZW3 / Comic Formats**: Direct modification or translation of fixed-layout PDFs, proprietary Kindle binaries (MOBI/AZW3), and pure-image archives (CBZ/CBR) is out of scope. These will be grayed out in the UI.
2. **Image Inpainting & Manga OCR**: Translating embedded pictures, comics, or manga via computer vision inpainting is out of scope. Images are strictly passed through untouched.
3. **Audio / TTS Generation**: Generating synchronized audiobooks or read-aloud tracks during translation is out of scope.
4. **Cloud Translation Synchronization**: Syncing active translation task states across multiple devices is out of scope; jobs execute strictly on the local machine.

## Further Notes

- **API Token Economy**: Users should be notified before launching large books of the estimated token cost (calculated as `approximate total word count * 1.5`).
- **Electron vs. Browser Compatibility**: All file manipulation logic is implemented using cross-platform Web APIs (`DOMParser`, `XMLSerializer`, `JSZip`, `Blob`, `ArrayBuffer`), ensuring complete compatibility whether running inside Electron desktop or a browser container.
